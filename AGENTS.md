# AGENTS.md

macOS/Linux dotfiles managed with **GNU Stow**. No tests, lint, CI, or build system — this is a configuration repository.

## Maintenance

When any config, script, or structure in this repo changes, update this file to keep it accurate.

## Repo location constraint

The repo **must** be cloned to `~/github/dotfiles-latest`. Paths are hardcoded to this location in `.zshrc`, `.zprofile`, `colorscheme-set.sh`, `kitty.conf`, and helper scripts.

## Key commands

| Command | Purpose |
|---------|---------|
| `./bootstrap.sh` | Full fresh-Mac setup: Xcode CLT → Homebrew → Brewfile → zsh → stow → colorscheme |
| `./setup.sh` | Stow all packages (interactive, prompts per package) |
| `./setup.sh zsh tmux` | Stow specific packages only |
| `./unstow.sh` | Remove all stow symlinks from `$HOME` |
| `./colorscheme-set.sh` | Interactive colorscheme picker (fzf menu) |
| `./colorscheme-set.sh tokyo-night` | Apply a specific theme directly |

## Stow structure

Each top-level directory is a Stow package that symlinks into `$HOME`. Exceptions (not stowed): `colorscheme/`, `assets/`.

`zsh/.stow-local-ignore` excludes `modules/`, `zshrc-*.sh`, `colorscheme-set.sh`, `readme.md`, `.gitignore` from symlinking — these are sourced directly from the repo path at runtime.

## Colorscheme system (do not edit generated files)

Theme definitions live in `colorscheme/list/*.sh` (each exports 24 `linkarzu_colorNN` shell variables). Running `colorscheme-set.sh` copies the chosen theme to `colorscheme/active/active-colorscheme.sh` (gitignored) and generates:
- `ghostty/.config/ghostty/ghostty-theme`
- `starship-config/.config/active-config.toml`
- `kitty/.config/kitty/active-theme.conf`
- `btop/.config/btop/themes/btop-theme.theme`

**Two `colorscheme-set.sh` scripts exist:**
- **Root `colorscheme-set.sh`** — newer, interactive, generates ghostty + starship only
- **`zsh/colorscheme-set.sh`** — legacy, takes a theme name as arg, generates kitty + ghostty + btop + starship + tmux + sketchybar + wallpaper (macOS only)

## Architecture: primary tools

- **Terminal:** Ghostty (primary, auto-starts herdr). Kitty is also configured (legacy, with sessions and remote control).
- **Multiplexer:** herdr (primary, prefix=Ctrl+Space). tmux is still configured (prefix=Ctrl+Space, tmux2k status bar) but secondary.
- **Editor:** Neovim (via `bob` version manager). `vim` aliased to `nvim`. Legacy `.vimrc` exists for sticky-notes/Obsidian use.
- **Shell:** ZSH with antidote plugin manager (auto-installs on first shell start).
- **Prompt:** Starship, config at `starship-config/.config/active-config.toml` (generated by colorscheme-set.sh). `starship.toml` in the same dir holds static symbol overrides only.
- **Window manager:** AeroSpace (in Brewfile, primary). Yabai config is legacy.
- **Runtimes:** mise (`mise.toml` manages only `lua`). Homebrew for everything else.

## herdr notes

- Config: `herdr/.config/herdr/config.toml` — prefix is Ctrl+Space (same as tmux)
- `prefix+g` opens lazygit popup; `prefix+shift+f` opens fzf folder picker (`herdr-open` script); `prefix+shift+t` opens sessionizer
- Helper scripts in `lazygit/.local/bin/`: `herdr-open`, `herdr-open-worktree`, `lazygit-ai-commit`, `sesh-open-worktree`
- `herdr-open` searches `~/dev`, `~/Workspace`, `~/dev/stackadapt`, `~/dev/stackadapt/web-worktrees` (depth-1, excludes node_modules/.git/etc.)

## lazygit custom config

- `editPreset: nvim-remote` — opens files in the parent nvim instance via `$NVIM` socket
- `Ctrl+A` in files panel — AI commit message generation (GitHub Models API, `lazygit-ai-commit` script, requires `gh` auth)
- `X` in branches panel — opens branch worktree in herdr (`herdr-open-worktree`)

## ZSH specifics

- `.zshrc` sources modules from the repo path (not symlinked): `history.sh`, `autocompletion.sh`, `aliases.sh`, `sesh.sh`
- Platform split: `zshrc-macos.sh` (eza, bat, zoxide, fzf via Homebrew) / `zshrc-linux.sh` (same tools with fallbacks)
- mise is activated twice: shims in `.zprofile`, `mise activate zsh` in `.zshrc`
- Aliases: `oc=opencode`, `cl=claude --effort xhigh --enable-auto-mode`, `cx=codex`, `rg` defaults to `--smart-case`, `fd` defaults to `--hidden --exclude .git`
- StackAdapt-specific aliases load only if `~/dev/stackadapt` exists (`sa`, `web`, `frontend`, `backend`, `down`, `wtpool`)

## Gitignored generated/runtime files

- `colorscheme/active/active-colorscheme.sh` — active theme (copied from list/)
- `tmux/.config/tmux/plugins/` — TPM plugins
- `lazygit/.config/lazygit/state.yml` — lazygit runtime state
- `zsh/.zsh_plugins.zsh` — antidote compiled plugins
